# conv2d on Kunpeng SME — 鲲鹏 HPC 挑战赛 S2 CONV 赛题

FP32 二维 valid 卷积 `conv2d(in, H, W, k, KH, KW, out)` 的 SME（FMOPA）实现。结果与参考实现逐位一致
（校验 1e-5 绝对误差，低于输出量级的 1 ulp，因此必须保持与参考实现完全相同的 fma 累加链），按 GFLOPS 计分。

## 运行

```bash
bash run.sh    # 编译 + 四个用例（题面判题口径：OMP_NUM_THREADS=38 numactl -N 1）
```

`run.sh` 在 CPU 节点旁探测到纯内存节点（HBM，无 CPU、1～32 GB、距离 ≤ 70）时会加
`--preferred=<node>`，让基准数据（四例合计 < 600 MB）落入 HBM；放不下自动回落本地
DDR，探测不到则不加参数（即题面原命令）。`CONV_HBM=0` 可关闭。资源仍为单一 NUMA
节点的 38 个 CPU，不改变算法与结果。

或手动：

```bash
gcc -O3 -march=armv9-a+sme+sve2 -fopenmp bench_conv.c conv2d.c -o conv2d_test -lm   # 或题面的 gcc -O3 ...（文件内 pragma 打开 SME）
OMP_NUM_THREADS=38 numactl -N 1 ./conv2d_test 4096 6144 39 39 1
```

运行期用 HWCAP2 检测 SME；硬件或编译器不支持时自动回退 SVE/标量通用实现（已覆盖多种形状的回退测试；当前 SME 内核要求 64 字节 SVL）。

## 核心思路

- FMOPA 外积对每个 ZA 元素恰是一次 fma。把卷积映射成外积序列，并保证每个输出元素的累加顺序与参考实现
  （kernel 行主序）完全一致 → 逐位精确。所有实现分支（滚动 / 经典 / SVE / 标量）都满足该性质。
- **滚动形态**（KH ≥ 16 且条带可行时启用，结构性条件，与具体用例尺寸无关）：tile 列 ↔ 输出行残差
  (s+c) mod KH，每列一条独立 fma 链，链满（KH 步）时 mova 切片直接落出连续输出，步数 = KW（X 方向零浪费）。
  残差按 KH 二进制分解成 16×1 对 / 单 16 / 8×2 / 4×4 组；余数残差折进 fmopa 旁并发的索引 fmla 链
  （每步 1 条 ld1rqw + 若干 fmla，链数按分解结构自动选 1/3/4），消掉低利用率的余数组。
- **v55 的 K9 余数组**：当 `KH % 32 == 17`、至少有两对 16 残差组且输出宽度 ≥ 128 时，
  两个 pair 各折入 4 条向量链，余下 9 行用“8 行 ZA + 1 行向量链”处理。例如 k81 从
  `32+33+16` 改为 `36+36+9`，减少矩阵乘加步数。输入每行先去交织成两个平面，内层直接连续加载，
  避免去交织与 FMLA 争用执行资源；每组单独记录折叠行的位置，保持每个输出的 FMA 顺序。
  较窄输出沿用原滚动分组，K9 的静态分配权重按实测成本调整为 1.40。
- **v56 的 K9 加载复用**：将每轮末尾已加载的四个偶平面向量留在寄存器中，供下一轮直接使用，
  每个常规双列迭代减少四次向量加载；把补零尾部移出主循环，并交错矩阵/向量乘加。
  每个输出的 FMA 顺序、输入读取范围、逐调用系数打包与跨块状态语义保持不变。
- **读取边界修复**：普通拷贝和 K9/K4 首次平面拷贝只读取有效输入，内部前缀与尾部补零；
  K4 尾部不再向上取整多读，K8 偶数核宽所需的额外元素在环形缓冲内补零。
- **经典形态**（其余形状）：tile 行 ↔ 输出列（stride 4），tile 列 ↔ 4×4 kernel 偏移，步数 (KH+3)(KW+3)；
  输入行去交织成 4 个平面驻留 L2 环形缓冲，a 向量用对齐载入 + `ext` 生成；整个 pass 的 Y 循环在一段汇编里，
  DRAM 预取、下一组的 ld4w 切片构建、已完成输出行的回写作为块组末尾的附加工作与 fmopa 交错。
  边界行（Y=0/1/KH+1/KH+2 只有少数列在干活）从 fmopa 循环移出，由并发的索引 fmla 半步完成。
- 滚动条带按 **8 个 kernel 高度周期**分块处理，保存 ZA 和 FMLA 的累加状态，下一块接续原来的 FMA 链，
  避免重复预热计算。线程先轮转处理本线程的相邻条带以复用输入；空闲后通过 CAS 接手其他条带的剩余行块，
  减少慢线程拖尾。状态只在本次调用内传递，每次调用重置进度。
- 每次调用都完整执行 kernel 打包，不缓存系数内容。使用 SVE gather 构造连续 R 向量，同一次调用中相同的
  完整 16 残差系数表共用一份；小表并行按组放行，大表由主线程按组构建并与计算重叠。
  可选并行打包现在每个 chunk 只有一个写入者，等待其完成后再读取。线程绑核取自继承的亲和掩码（兼容 numactl/taskset），
  自有线程池调用间自旋（等价 OMP_WAIT_POLICY=ACTIVE）；经典形态保留原来的 pass 调度与回写策略。

## 当前本地 v56

已整合上游 `b9591de` 的按组打包、行拷贝重叠与 K4 调度，保留本地 K9 加载复用，
并修复 K8/K9/K4 读取边界及可选并行打包的重复写竞争。当前算子 SHA-256：
`695c449ccdc0b234ae16812a49b26afc7a7d0153d5d0b33983c7b3a281f3530b`。

服务器验收包括 2,824 项审计/保护页/状态检查（含必须检出旧版缺陷的阳性对照）、
480 次筛选计时哈希、72 次原始基准完整校验和三个候选包共 12 次完整校验。
两个修复候选的已审计拷贝区间越界数均为零，输出逐位一致。
这不等同于对所有汇编访问、分配失败或多个调用者并发调用的全面保证。

显式指定相同 mode 3 的对照为 +0.05%。复测没有重现稳定的 2% 回退，但此前两轮偏慢的
根因尚未确定，不能声称全部用例稳定加速。剖析中该形状约 86% 的内核时间仍在主计算组，
这是后续优化重点之一。详见 `docs/v56-experiments/planar-fix.md` 和原始日志。

## 环境变量（实验与回退）

`CONV_ROLL=0` 强制经典形态；`CONV_POOL=0` 回退 OpenMP 并行区；`CONV_BR=0` 关边界行方案；
`CONV_SP`/`CONV_STORE`/`CONV_PFL2` 等微调项见 `conv2d.c` 的 `read_knobs()`；`CONV_NO_SME=1` 强制通用实现。
`CONV_PROFILE=1` 输出分相计时（stderr）。
滚动诊断中的 `8x2` 统计桶同时包含 K8 和新增的 K9 内核。
