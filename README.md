# conv2d on Kunpeng SME — 鲲鹏 HPC 挑战赛 S2 CONV 赛题

FP32 二维 valid 相关运算 `conv2d(in, H, W, k, KH, KW, out)`，核不翻转。
严格保持参考实现的 `(kernel row, kernel column)` FMA 累加顺序；题目校验为
`1e-5` **绝对误差**。四个正式用例与编译命令见 [题面](docs/problem.md)。

## 当前版本 v52

2026-09-12，cn20481，38 核、约 1.55 GHz，CPU NUMA 1 + HBM 17。
下表使用题面编译命令和官方 `bench_conv.c`：同节点交替运行基线与候选，
各五轮，每轮计时五次；表中为五轮 GFLOPS 的中位数。
**这是服务器实测，不是线上评测机的换算值。**

| 用例 | v51 基线 | v52 | 变化 |
|---|---:|---:|---:|
| 4096×6144，39×39 | 14042.5 | 14350.9 | +2.20% |
| 6144×4096，41×41 | 14074.7 | 14211.9 | +0.97% |
| 4256×6390，55×55 | 14564.8 | 14543.6 | −0.15% |
| 6390×4256，81×81 | 14519.9 | 14537.6 | +0.12% |

主要改动：

- 在 `k16pairf4` 中按四个向量展开输入行拷贝，减少地址递增和循环分支；
  默认分组中的 39×39 用例使用此路径。其他内核保留原拷贝循环。
- 重建分组时保留打包缓冲区指针及容量，修复切换卷积核时的内存泄漏。
- 卷积核副本容量允许大于当前核大小，避免大核切换到小核后反复打包。

缓存回归实测：循环切换 81/39/39/55 卷积核，共 32 次调用，跟踪的对齐缓冲区
占用由 v51 的 212 MiB 降为 12 MiB；首轮尺寸循环后新增分配从 91 次降为 0。
这不是进程总 RSS。所有输出均逐位一致。

验证：正数和正负混合输入各 166 项严格逐位比较、19 项固定/高度复用测试，
以及正式候选的 20 次官方完整校验均通过。官方用例最大绝对误差为 **0**。
39×39 在五轮配对比较中均提速；41×41 基线波动较大，其收益证据弱于 39×39。
55×55、81×81 基本持平。原始日志见 `results/v52/accept.log`。

未采用有损量化：BF16、FP16，甚至仅舍入掉 FP32 尾数最低一位，都在数值实验中超差。
无损紧凑系数打包虽然正确且更省空间，实测更慢，也未采用。
本轮实验方法和失败方向见 [v52 记录](docs/v52.md)。v51 的尾部裁剪、输出预取移除
及高度缓存修复继续保留，之前的测量见 [v51 记录](docs/v51.md) 和 [历史笔记](NOTES.md)。

## 编译运行

```bash
gcc -O3 bench_conv.c conv2d.c -o conv2d_test -lm -fopenmp
OMP_NUM_THREADS=38 numactl -N 1 ./conv2d_test 4096 6144 39 39 1
bash run.sh
```

`run.sh` 加载 HPCKit，优先使用 CPU 节点 5（回退 1、0），并在允许时选择邻近 HBM。
这与上表固定 CPU 节点 1 的测量配置不同；复测时应保持线程、频率及内存放置一致。
运行期检测 SME + FA64，无 SME 或编译器不支持时使用 SVE/标量通用实现。

## 目录

- `conv2d.c`：四例默认采用滚动 SME FMOPA + FMLA 内核；保留经典 SME 和通用实现。
- `bench_conv.c`、`run.sh`：官方基准与提交入口。
- `tools/test_conv.c`：泛化测试；`TEST_BITWISE=1` 启用严格逐位比较，`TEST_SIGNED=1` 使用正负输入。
- `tools/fbench.c`：带参考哈希缓存的快速测试；最终验收仍使用官方完整参考。
- `tools/quant_audit.c`、`tools/gen_v51.py`、`tools/gen_v52.py`：量化审计与可复现候选生成。
- `tools/test_pack_reuse.c`：切换卷积核的逐位正确性与对齐缓冲区复用回归。
- `jobs/`、`probe/`：Donau 作业脚本与微架构探针。
- `results/v52/`：本轮服务器实测日志；`submissions/conv.zip`：正式提交包。
