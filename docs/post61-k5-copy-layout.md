# K5 输入平面前缀布局对照

基于上游 v61 `b3140af / 2c406547`，不叠加已拒绝的输出清零重排。
用户要求持续本地优化、定期 pull、明确要求后才 push；本轮不发布。

当前 K5 对每行 `KW+191` 个活跃输入做三平面拷贝。原实现按输入地址补 `0..15` 个
前缀元素，将源起点对齐到 64 字节；完整 LD3W、向下取整的谓词 LD3W、末尾 0..2 次
标量加载共同保证读取不过末端。尾部标量处理及较大的对齐前缀可能增加开销。

本轮同一候选源码、同一测速二进制，首次读取 `CONV_K5_COPY` 后选择：

| 设置 | 前缀 sh | 作用 |
| --- | --- | --- |
| 0 / baseline | 原输入地址的 float 偏移模 16 | 保持原有对齐政策 |
| 1 / exact | 0 | 不复制前缀，源地址可能不对齐 |
| 2 / triples | `(3-(KW+191)%3)%3` | 用至多两个前缀元素让长度成为 3 的倍数，跳过标量尾部 |

仅新增实验配置和 K5 的 sh 选择表达式。所有内联汇编、系数构建、分组、调度和其他内核
逐字节不变；逆向替换可恢复完整原源码。但初始参数和实际输入/内部缓冲地址会随 sh 改变。
同一个新二进制消除不同候选布局造成的混淆；设置 0 仍含配置选择开销，不能把它称为
与原始 v61 完全相同的二进制。候选采用仍须生成固定政策源码并独立完整验收。

## 几何与边界

宿主检查覆盖 KW 1..400、16 种输入对齐、3 种设置，共 **19,200** 组。
按每个平面的首末读取位置验证 `q+3*j` 的输入映射与内部 stride 容量，所有拷贝总长
均恰为 `KW+191+sh`，末端保持 `KW+191` 个活跃元素。设置 2 的标量尾部恒为零。
这是几何模型，不是对全部汇编读取的动态证明。

第一行由现有 helper 仅从活跃输入初始化，前缀和内部空位补零；后续汇编读下一行，
最后一次读当前行。因此前缀读取发生在非首行，仍需由实际调用区间审计和保护页验证。
没有向上扩大末端谓词或以未使用的 lane 为由越界读取。

KW41 时，若条带输入的 float 对齐偏移为 0，原对齐设置需要 4 个完整 48 元素块、
13 个尾部三元组及 1 个标量；偏移为 8 时是 5 个完整块、零尾部。设置 2 统一为
4 个完整块、14 个尾部三元组、零标量，stride 都为 96 floats。代价是源读取不再保持
原来的 64 字节对齐。以上是条件示例：官方基准使用 malloc，不能假定输入总是
64 字节对齐，也不能把某一偏移对应的尾部指令数当作已测进程的实际分布。
