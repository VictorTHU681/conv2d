## Hypothesis

The new K9 kernel groups four FMOPA instructions, then eight vector FMLA
instructions, twice per KW pair. Its two-plane input layout has removed inner
LD2W deinterleaving, but the instruction stream still presents bursts of work
to the matrix and vector units. It also checks the real-KW countdown twice per
pair, although only the final pair can contain padding. Earlier v55 scheduling
experiments predate K9 and do not test this new kernel.

`tools/gen_v56.py` compares:

- `k9weave`: interleave two independent vector accumulator updates after each
  matrix update. Retain guards; the no-FMLA padding path duplicates OPA so
  guards cannot suppress required matrix steps. This adds a branch to each
  guarded half and is not a pure instruction-permutation control.
- `k9split`: execute floor(KW/2) regular pairs without per-half real-KW tests,
  followed by one dedicated padding pair. For odd KW, only its first half
  updates vector accumulators; for even KW neither half does.
- `k9both`: combine the split main loop and interleaving. The regular loop
  interleaves without the extra guard-path branches.

All controls retain exactly the existing matrix operand order and each output
vector's sequential FMA chain. The last padded pair is required for matrix
output offsets even when KW is even. Source preparation, output events,
coefficient wrap, resumable state and task planning are unchanged. Kernel
compilation can still affect code layout outside the changed function, so the
screen covers all four official shapes, not only k81.

Reproduce sources with `python3 tools/gen_v56.py`; hashes are recorded in
`results/v56/sources.sha256`. The server job first runs signed bitwise extended
K9 cases and generalized cases for all four variants, then five alternating
process rounds for each shape in DDR and HBM. Timed results use the existing

not final official acceptance.

## Carry loaded vectors across adjacent KW pairs

Inspection of the K9 sequence reveals four redundant even-plane loads per
regular KW pair: the second FMLA step loads the next even-plane vectors, then
the next iteration immediately loads the same addresses again. The odd-plane
vectors are still needed by the second matrix step and cannot be handled the
same way. `tools/gen_v56_reuse.py` preloads the four even vectors before the
KW loop and retains those loaded by the second FMLA step for the next pair.
It tests the original grouped loop (`k9reuse`) and the split/interleaved loop
(`k9reuseboth`). The split variant retains its separate one-off tail loads.
No source read is added, the prepared input span is unchanged, and copying a
new row is followed by fresh preloads before computing that row.

The two new variants compile successfully. Job **1580758** screens them against
v55 with extended signed cases and five alternating process rounds. All
candidates remain under ignored `build/v56/`; nothing is promoted to conv2d.c.
