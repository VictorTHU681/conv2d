# v51 experiments (2026-09-12)

## Retained implementation and official acceptance

The retained candidate is `combo`: K4 zero-tail trimming, removal of output
prefetch/address setup in the five 16-row rolling kernels, and the height-cache
fix. Production `conv2d.c` is byte-identical to the tested candidate, SHA-256
`e8e6b3f08c50c4e5cfd50906a99e171ade548a56097f7151ffb9f2aaa5056315`.

Job `1579108` succeeded on cn20493, CPU node 1 + HBM17, 38 threads, about
1.55 GHz. `results/v51/accept.log` contains the complete raw output.
Official benchmark medians of three alternating processes, each averaging three
timed calls, are:

| Kernel | Immutable v50 baseline | Retained v51 | Change |
|---|---:|---:|---:|
| 39 | 13774.8561 | 14138.1070 | +2.637% |
| 41 | 14147.3601 | 14121.1202 | −0.185% |
| 55 | 14523.5894 | 14553.9417 | +0.209% |
| 81 | 14341.3907 | 14564.7352 | +1.557% |

The sum of these four measured rates rises 1.040%; this is a descriptive summary,
not a claim about the contest's aggregate scoring formula. k41/k55 changes are

The retained candidate passed 166/166 positive and 166/166 signed-data cases with
strict bitwise comparison, plus 19/19 fixed/height-reuse cases. All 12 official

candidate had maximum absolute error zero. Plain-command GFLOPS were
14143.4269 / 13881.8037 / 14569.2147 / 14538.9668.
The alternative that preloads the K4 tail count also passed, but its official

## Precision gate

`tools/quant_audit.c` recreates the official complete input and kernel matrices,
with the same RNG seeds and 38-thread static initialization. It samples 256
output positions per official case, including all four corners, and compares
ordered `fmaf` chains after operand rounding against the original FP32 chain.
This is a feasibility survey, not a replacement for the full official validator.

The WSL survey (`results/v51/quant_audit_wsl.log`) rejects every tested lossy
representation, even kernel-only rounding that drops just one mantissa bit:

| Kernel | Kernel-only 22-bit mantissa failures | Maximum absolute error |
|---|---:|---:|
| 39 | 76/256 | 0.0000610351562 |
| 41 | 103/256 | 0.0000610351562 |
| 55 | 85/256 | 0.000183105469 |
| 81 | 83/256 | 0.000366210938 |

FP16 and BF16 fail much more strongly. These results exclude the tested direct
lossy operand conversions; they do not claim to rule out every possible exact
encoding or compensated algorithm. The production kernel remains full FP32.
The survey is also run on the allocated Arm compute node.

## Same-node screening

Generate immutable baseline and candidate sources:

```sh
python3 tools/gen_v51.py
```

Candidates preserve each output's accumulation order:

- `unroll2`, `unroll4`: unroll the inner loops of the five 16-row rolling kernels.
- `k4tail`: omit the final all-zero coefficient steps introduced by rounding
  the K4 row length up to a multiple of four; keep the packed-table row stride.

`jobs/v51_job.sh` compiles each candidate, runs forced-rolling generalized
correctness cases, obtains official baseline results, and runs three alternating
candidate-order rounds of the hash-checking benchmark, five timings per process.
The cached-reference benchmark supplements the official benchmark; final
acceptance of a retained candidate must use the complete official validator.

Remote directory: `/home/share/niujiayin/conv2d-opt-20260912`.
Donau submission requests 38 CPUs in one NUMA node and 4 GiB memory. The script
uses only CPUs and memory nodes allowed by the allocation. HBM is selected only
when the allocation permits it; otherwise normal allowed memory is used.

The first job (`1578964`, cn20485) stopped before numerical testing because HBM
node 16 was visible in sysfs but outside the job's allowed memory mask. The
placement script was corrected to check `Mems_allowed_list` before selecting HBM.
No performance or correctness claim is based on that failed setup run.

node. The placement probe now tries `sched_setaffinity` in a child and verifies
the effective mask, so it respects the kernel-enforced cpuset rather than
mistaking the initial shell binding for the allocation boundary.

Performance results and retained changes will be added after further measurement.

## Exact compact packing candidate

The old 16-row packed table stores every overlapping 16-element kernel window
separately: `R[y][x][c] = k[(y-c) mod KH][x]`. The `compact` candidate instead
stores a reversed cyclic height sequence for each kernel column:
`T[x][r] = k[(-r) mod KH][x]`, extended by at least 15 elements. A vector load
starting at `r=(-y) mod KH` produces exactly the original 16 FP32 values.
No operand is rounded and the ordered FMOPA/FMLA chains are unchanged.

| Kernel | Old R bytes/group | Compact R bytes/group | Reduction factor |
|---|---:|---:|---:|
| 39 | 97344 | 9984 | 9.75 |
| 41 | 107584 | 10496 | 10.25 |
| 55 | 193600 | 17600 | 11.00 |
| 81 | 419904 | 31104 | 13.50 |

This table excludes the separate FMLA coefficient table, input rings, and
unchanged K4/K8 groups. Smaller packing is not itself evidence of a speedup:
the candidate trades aligned L2 loads for overlapping, often unaligned L1 loads
and adds row-wrap instructions. The index mapping and wrap were exhaustively
checked for every row/lane at KH=16..100; Arm GCC assembly compilation passed.
Compute-node correctness and timing are required before adopting it.

## HBM screening and height-cache regression

Job `1579032` completed on cn20484, CPU node 1 + HBM node 17, at about
1.55 GHz. Raw evidence is in `results/v51/screen5.log`. All seven candidates
passed 56/56 generalized tests and all 420 timed outputs passed reference hashes.
The same-node local-DDR control reproduces the lower throughput, so the earlier
restricted-placement scores must not be used to claim an algorithmic speedup.

| Variant | k39 | k41 | k55 | k81 |
|---|---:|---:|---:|---:|
| baseline | 13778.7 | 14189.4 | 14505.0 | 14368.6 |
| k4tail | 14072.4 | 14174.8 | 14498.8 | 14309.8 |
| full | 13842.8 | 14149.3 | 14459.4 | 14239.8 |
| nopfo | 13820.9 | 14239.3 | 14507.5 | 14522.6 |
| pfol1 | 13795.3 | 14031.3 | 14493.4 | 14313.1 |
| pfoextra | 13799.2 | 14104.6 | 14452.6 | 14282.6 |
| compact | 13539.4 | 13766.4 | 12794.1 | 13209.1 |

Values are medians of 15 timings, not extrapolations to the online judge.
Compact packing is rejected: correct values and smaller tables did not yield
faster execution. K4 tail trimming (+2.13% k39) and output-prefetch removal
(+1.07% k81) advance to combined testing and official-validator acceptance.

The same job also reproduced a pre-existing correctness bug: with the exact same
81×81 kernel and input width 1200, calls at H=100 followed by H=104 and H=108
reuse a work partition built for H=100. Baseline left 4480 and 8960 output
elements unwritten, respectively. The expected failing control is deliberately
present in the raw log. `rplan_t` now records the output height and rebuilds the
partition when it changes; kernel packing can still be reused. The fix passed
59/59 cases including height reuse, plus 56/56 signed-data cases, with strict
bitwise comparisons enabled. This fix is independent of performance candidates.
