## Precision gate

`tools/quant_audit.c` recreates the official complete input and kernel matrices,
with the same RNG seeds and 38-thread static initialization. It samples 256
output positions per official case, including all four corners, and compares
ordered `fmaf` chains after operand rounding against the original FP32 chain.
This is a feasibility survey, not a replacement for the full official validator.

The WSL survey (`results/v51/quant_audit_wsl.log`) rejects every tested lossy
representation, even kernel-only rounding that drops just one mantissa bit:

| Kernel | Kernel-only 22-bit mantissa failures | Maximum absolute error |
|---|---:|---:|
| 39 | 76/256 | 0.0000610351562 |
| 41 | 103/256 | 0.0000610351562 |
| 55 | 85/256 | 0.000183105469 |
| 81 | 83/256 | 0.000366210938 |

FP16 and BF16 fail much more strongly. These results exclude the tested direct
lossy operand conversions; they do not claim to rule out every possible exact
encoding or compensated algorithm. The production kernel remains full FP32.
The survey is also run on the allocated Arm compute node.

## Same-node screening

Generate immutable baseline and candidate sources:

```sh
python3 tools/gen_v51.py
```

Candidates preserve each output's accumulation order:

- `unroll2`, `unroll4`: unroll the inner loops of the five 16-row rolling kernels.
- `k4tail`: omit the final all-zero coefficient steps introduced by rounding
  the K4 row length up to a multiple of four; keep the packed-table row stride.

`jobs/v51_job.sh` compiles each candidate, runs forced-rolling generalized
correctness cases, obtains official baseline results, and runs three alternating
candidate-order rounds of the hash-checking benchmark, five timings per process.
The cached-reference benchmark supplements the official benchmark; final
acceptance of a retained candidate must use the complete official validator.

Remote directory: `/home/share/niujiayin/conv2d-opt-20260912`.
Donau submission requests 38 CPUs in one NUMA node and 4 GiB memory. The script
uses only CPUs and memory nodes allowed by the allocation. HBM is selected only
when the allocation permits it; otherwise normal allowed memory is used.

The first job (`1578964`, cn20485) stopped before numerical testing because HBM
node 16 was visible in sysfs but outside the job's allowed memory mask. The
placement script was corrected to check `Mems_allowed_list` before selecting HBM.
No performance or correctness claim is based on that failed setup run.

## First completed screening: restricted placement

Job `1578971` completed on cn20483, CPU node 0 (CPUs 0–37), with memory
nodes 0–15 permitted and HBM excluded. Reported CPU frequency: 1.549084 GHz.
All seven variants passed 56/56 forced-rolling tests; all 420 timed outputs
passed reference-hash checks. The Arm quantization survey exactly matches WSL.

The complete official baseline validator reported zero maximum absolute error
for all four cases, at 7863.5077 / 8549.1061 / 10750.2350 / 14221.4129 GFLOPS.
These are new measurements, not the old README scores.

Median GFLOPS across 15 timed runs per candidate/case:

| Variant | k39 | k41 | k55 | k81 |
|---|---:|---:|---:|---:|
| baseline | 7848.8 | 8726.2 | 10723.3 | 14228.5 |
| unroll2 | 7847.4 | 8649.3 | 10326.6 | 14154.7 |
| unroll4 | 7839.8 | 8329.6 | 10424.5 | 14079.2 |
| k4tail | 7885.7 | 8558.7 | 10773.7 | 14308.5 |
| offset2 | 7609.8 | 8636.8 | 10709.3 | 14245.9 |
| offset4 | 7594.0 | 7317.1 | 10241.8 | 13943.6 |
| full | 7818.5 | 8868.5 | 10620.4 | 14056.5 |

`offset2/4` also consolidate pointer advances and use immediate-address offsets.
`full` fully unrolls the known kernel widths while retaining a generic fallback.
No candidate is accepted from this screening: improvements are small or mixed,
and the first three baseline scores differ substantially from historical runs.
Raw evidence: `results/v51/screen2.log`; summarize with
`python3 tools/summarize_v51.py results/v51/screen2.log`.

Subsequent screening tests output-prefetch removal, L1 destination hints and
coverage of the final partially covered cache line, and compares local DDR to
allowed HBM. A no-affinity submission initially stopped because its shell
inherited only the 16 service cores, although the queue allocates an exclusive
node. The placement probe now tries `sched_setaffinity` in a child and verifies
the effective mask, so it respects the kernel-enforced cpuset rather than
mistaking the initial shell binding for the allocation boundary.

Performance results and retained changes will be added after further measurement.
