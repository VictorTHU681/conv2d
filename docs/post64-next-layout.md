# PAIRF3 系数表紧凑布局（已复验，未采用）

K4的小幅指令排列/寻址变化尚未形成可采用收益。下一项转向kind34的系数表布局：
目前PAIRF3每步存四个float，前三个有效，第四个为零；LD1RQW加载后只用前三个indexed-FMLA系数。
拟保持相同LD1RQW与FMA顺序，将步距从四个float缩为三个，从工作集而非指令排列寻求收益。

不能简单把整张表平铺成KH*steps*3：每行最后一次16字节读取会触及下一行，
并行按行打包时可能读取另一个chunk正在写的数据，即使第四通道没有参与运算也不妥。
因此拟给每行独立增加一个padding float，由该行唯一打包者初始化，再发布该行完成状态。

拟定行距为3*steps+1个float：步内游标加12字节，整行完成后加4字节跳过padding。
需要一起修改分配容量、roll_pack_chunk、worker的kb0/kend、F3的行跨度和行末回绕。
F4维持原四系数布局，首行偏移和续算相位仍使用原有pc->af/cf；每次调用仍重新打包，禁止复用旧系数内容。

已检查当前代码：F3有独立的行末kf回绕逻辑，不使用PAIRF4_TAIL；新增padding跳过应置于
OVL_LOOP(PAIRF3_STEP)之后、kf表尾比较之前。动态并行安全、最后一行加载范围和跨调用复用需要重点验证。

预期代价是LD1RQW的对齐变差，可能抵消较小工作集的好处。分配器粒度也可能使物理分配量不下降；
只能先声称逻辑系数表缩小，不能预先宣称RSS下降或性能提升。
