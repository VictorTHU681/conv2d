# 更大 FMLA 折叠组的初步可行性判断

在等待F3布局对照时，检查了另一方向：对原35+16+4分组，把最后四个残差也并入pair，
形成39+16，从而去掉K4尾组。这里只是设计评估，未生成算子、未提交新测量，不能称为已证伪实现。

该F7设计每步需要14条indexed FMLA，而F3是6条，F4是8条。
已有作业1586070的纯寄存器混合探针在0..8条FMLA时四FMOPA步约5.162ns；
10条约6.452ns，12条约7.742ns，16条约10.323ns。
[已完成的探针与范围](v56-experiments/arithmetic-gap.md)、
[原始汇总](../results/v56/experiments/arithmetic-gap/summary.md)、
[探针生成器](../tools/gen_v56_mixed_probe.py)。
这些是旧作业/旧节点的实测，不是当前F7内核性能或所有指令排列的硬件定律。

粗略稳态模型对同一outW*KH*KW工作量归一化，忽略块尾、padding/相位预热及不均衡：
当前F3/SINGLE/K4分别用mix6/32、mix0/64、mix0*(steps4/KW)/256。
假想F7/SINGLE用mix14/32+mix0/64。没有实测mix14，以下分别使用mix12乐观代理、
以及mix12/mix16中点作纯建模假设；两者都不是严格下界或F7必然耗时。

以KW55、K4步数60为例，当前模型值0.263943，12-FMLA代理0.322596（+22.22%），14-FMLA插值0.362923（+37.50%）。单位为上述归一化后的ns。

这提示删除较小K4尾组的收益，可能不足以抵消主pair每步增加8条FMLA的代价，
因此目前不优先实现F7，不把“大折叠组”直接当成优化。
若未来有不同的指令排列或新的探针证据，再重新评估，而不是把本模型当成永久否定。

实现还有实际容量约束：七条输出链需要14个64B累加向量，连同4096B ZA为4992B，
超过当前每片4608B的carry容量。若未来实现，必须同步处理状态分配/步距、保存恢复、
分组、系数打包、行相位和所有权依赖；不能只把nf从3改7。
本分析不修改默认算子、提交包或编译命令，未push。
