# v65：PAIRF3 纯计算循环四步展开

本次按用户授权汇总发布一次，基于上游138dcac（上一发布版本v64）。
采用普通内联u4，源码SHA-256：
`f88b3f90295fd5ad5a749016343b266535857b53d2588801f65e18e6c7f2d499`。

F3每四步合并系数指针更新，完整计算循环从84条指令减少到69条。
保留原系数布局、穿插拷贝、补拷、逐步FMA顺序、余数处理和跨块续算。
分组、自动打包策略及原子完成通知未改。独立代码段方案不纳入本次源码，正式程序仍为普通内联汇编。

## 正确性、程序一致性及范围

采用的u4通过1,953项状态/保护页检查：五种打包模式、跨调用输入及系数变化、跨块续算、
NF=3路径和F3余数边界。三次对照合计336次完整参考校验全部最大误差零，
其中u4为144次，其余为上游和未采用布局对照。
普通、NF=3、诊断三个验收包另有12次完整参考校验通过。

原始计时二进制哈希在各作业中一致。普通包按正式文件名和命令编译，其.text段与计时u4字节相同，
见[代码段审计](../results/post64/pairf3-packages/formal_text_audit.txt)。
最终发布包只更新验收包中的README；三个程序成员（算子、基准、运行脚本）保持验收字节，
由[发布打包器](../tools/package_v65.py)逐成员校验。
[发布包哈希](../results/v65/archives.sha256)、[成员审计](../results/v65/member_audit.txt)、
[与服务器验收包直接比较及可重复打包](../results/v65/qualification_audit.txt)。
编译仍为 `gcc -O3 bench_conv.c conv2d.c -o conv2d_test -lm -fopenmp`，原run.sh/run_diag.sh未修改。

没有新增答案缓存、调用阶段跳过、精确公开尺寸分派或机器负载探测。
64字节SVL、外部多调用者并发、分配失败处理等既有限制仍在；诊断包仅用于诊断，普通conv.zip用于正常提交。
本轮检查不等于完整赛事规则认证，历史[合规范围](v56-compliance.md)继续适用。

## 同批汇总的未采用工作

- PAIRF4展开、独立函数与对齐；K4标量/寄存器复制、加载调度、带索引存储与输出事件排序：没有形成可采用的稳定整体收益。
- PAIRF3紧凑系数表：KH55两种内存约回退0.6%，拒绝。
- F3独立展开代码段：三方对照KH55仅+0.06%/+0.11%，对普通u4没有稳定额外目标收益，同时增加布局和符号归属复杂度，不采用。
- 轮间哈希诊断与更大折叠组可行性分析：作为实验依据，不作为已实现加速。

完整记录见[后续优化总览](post64.md)。本次只汇总推送一次，不给内部试验逐次递增发布版本。
