# v54 —— 每次调用打包的提速与重叠（2026-09-12）

基线 v53（commit `944c6b1`，md5 `2ffcd6b3`）。约束不变：打包结果不跨调用缓存，
每次调用从 kernel 参数无条件全量重建 R/kf（v51 合规口径）；本版只让"每次都做的打包"更快、
更早让计算开工。

## 改动（conv2d.c，md5 `101b542d`）

1. **R 表跨组共享（调用内去重）**：16 族组（kind 32/33/34/35/16/17）的表内容
   `R[y][X][c] = k[(y-c) mod KH][X]` 只依赖 (KH, KW, steps) 与零掩码；s_base 的差异由内核起始
   计数器（yA0/cA0）承担。无零掩码（s_base+15 < KH）且 steps/RSB 相同的组逐位相同 →
   指向首个此类组的缓冲，同一次调用内只构建一份。k55 省 single16 表（30%），k81 三表并一（省 2/3）。
2. **对角行构建**：R[y][X][c] 与 R[y-1][X][c-S]（S = 每 sidx 列数：16 族 1、8×2 2、4×4 4）的
   kj/ic 完全一致 → 整行 = 上一行右移 S 列（NEON vext/寄存器复制）+ 每 X 补 S 个鲜值
   （kind4 另按 nv 重清零越界 sidx 列）。打包 chunk 改为 (组, 8 行块)：块内首行标量、其余 7 行
   对角，块自包含、幂等，可乱序/重复执行（并行认领路径不变可用）。kf 主体用 vst4q 交织。
   逐位与标量路径相同（纯位拷贝 + 相同鲜值载入）。
3. **按组重叠放行（默认，CONV_PACKSER=1/auto）**：主线程在 worker 唤醒后按组串行打包
   （保持单写者局部性——实测 8 行快块的全体并行打包仍全面更慢：认领/扫描同步 + 计算期读表
   变跨核搬运），每写完一组 release 一条 gdone 线；工作线程认领工作项后、用到某组前 acquire
   等待该组。多数线程首片在组 0，比"全部打包完再放行"早开工 ~25-50 µs。
   `CONV_PACKSER`：1/auto = 重叠串行、2 = 串行不重叠（对照）、0 = 全体并行（超大表）。
4. `[roll prof]`（CONV_PROFILE=1）打印 prep/pack/region 相位。

打包耗时（DDR，串行不重叠口径）：k39 55 µs、k41 58 µs、k55 95 µs、k81 68 µs
（v53 为标量串行 k39/k41 ~85 µs，k55/k81 并行 chunk，成本相当）；重叠后大部分移出关键路径。
