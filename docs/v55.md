## Architecture questions

v54 fixes most DDR locality and worker-tail loss. The remaining cost needs
comparison against measured hardware throughput, separating four-tile FMOPA
from concurrent FMLA, memory supply, output events, packing, and state transfer.
The throughput model is optimistic: it omits warmup, state transfer, output,
packing, and scheduling. It is not a forecast of attainable end-to-end speed.

1. ZA state is currently saved/restored as 64 directly addressed array vectors.
   Test four-way unrolling and explicit ZA ↔ Z ↔ memory transfers.
2. The input ring was introduced before resumable row blocking. Test whether
   v54 locality makes direct input loads competitive, using L1/L2 prefetch
   controls and retaining K4's independent deinterleaving path.
3. Preserve exact FP32 FMA order and rebuild coefficient contents on every call.
   Test each candidate with signed bitwise cases and tall multi-block cases.

## Literature used to choose experiments

- [Remke and Breuer, *Hello SME!* (2024)](https://arxiv.org/abs/2409.18779)
  studies arithmetic and ZA-transfer microbenchmarks on Apple M4. Its observation
  that two-step ZA transfers outperform direct transfers motivates a local
  control; it is not assumed to hold on Kunpeng.
- [Deng et al., *Demystifying ARM SME to Optimize General Matrix Multiplications*
  (2025)](https://arxiv.org/html/2512.21473v1) emphasizes cache/TLB-aware blocking,
  packing and multi-vector loads on M4 Pro. Its cache sizes, shared SME-unit
  topology and SME2-specific instruction advantages are platform-specific.
- [Arm's SME programming guide](https://developer.arm.com/documentation/109246/0100/matmul-fp32--Single-precision-matrix-by-matrix-multiplication/preprocess-l-function-overview?lang=en)
  describes horizontal/vertical ZA access for matrix preprocessing. This suggests
  a later packing control if measured packing time remains significant.

Mixed-precision speedups and reduction reassociation from general GEMM work do
not satisfy this task's strict ordered-FP32 result requirement.

## Next experiment: reuse adjacent convolution-step vectors

`tools/v55_shift.py` unrolls two consecutive KW steps. The first step loads an
extra end vector; two/four `ext` instructions form the next step's input
vectors, reducing repeated unaligned loads without changing FMA order. A
control unrolls the loop without vector reuse to separate branch savings.
The pair-plus-four-FMLA kernel is deliberately excluded because the measured
FMLA issue budget leaves no spare vector instructions there. Pair, pair-plus-one,
pair-plus-three, and single-sixteen kernels have spare vector issue capacity.
The variants compare all eligible kernels, single-only, pair-plus-three-only,
and ordinary two-way unrolling. They retain the original ring and packing.

## Local continuation: interleaved arithmetic scheduling

`tools/v55_schedule.py` generates `weaveall`, `weave3`, and `weave4` from the
same immutable v54 baseline. Within each KW step, these interleave four FMOPA
instructions with the existing independent FMLA chains. The one-row kernel's
broadcast moves before arithmetic. No FMA operand, per-output accumulation
order, coefficient mapping, vector register allocation, or memory address is
changed. This asks whether instruction ordering improves queue/issue overlap;
it is a hypothesis, not a measured gain. It differs from v54's rejected
cross-iteration ping-pong and look-ahead register variants.

`jobs/v55_schedule_job.sh` is prepared but **not submitted**. It compares the
three candidates and baseline using signed tall and randomized bitwise tests,

in DDR and HBM, with the existing compiler flags and placement policy.

## K4 structured memory instruction controls

`tools/v55_k4_io.py` tests the slower K4 residual kernel's data preparation
and output, leaving its FMOPA loop and arithmetic mapping intact:

- `k4cpz`: replace full-vector LD4W with four LD1W and eight UZP operations;
  retain predicated LD4W tails and their existing bounds handling.
- `k4evz`: replace ST4W with eight ZIP operations and four contiguous ST1W.
- `k4ioz`: combine the two, with explicit additional Z-register clobbers.

Symbolic lane tracking of the generated permutations preserves all 64 float
positions in each direction. The combined source compiles with server GCC
using the unchanged flags. Job **1580036** tests all three candidates against
v54 with signed correctness and alternating DDR/HBM timing. It was submitted
at 22:05 and has not yet yielded an accepted performance result.
