## Restarted row blocks: locality wins, arithmetic overhead loses

Job `1579688` completed on cn20483, 19:15:58–19:18:30 +08:00, CPU1 + HBM17
available, 38 threads. All six builds passed 83 signed bitwise cases; all
600 candidate timing outputs and the phase-build timing outputs passed hashes.
The baseline and each candidate ran in three alternating process rounds with
five timed calls each, separately on DDR and HBM.

Splitting strips into row-major blocks improves input locality but repeats the
KH−1 warm-up rows for every block. In screening, 512-row blocks improve DDR
k39 by about 33%, k55 by 13%; 256-row blocks improve DDR k41 by about 38%.
The same changes regress HBM by 5–23%, and k81 also regresses on DDR. Therefore
these are **not accepted optimizations**. They are evidence motivating a
locality-preserving scheme that does not repeat warm-up arithmetic.

Raw log: `results/v54/block.log`; reproduce summaries with
`python3 tools/summarize_v54.py results/v54/block.log`.

## Carrying accumulators between blocks

The carry candidates save/restore the full 4096-byte ZA array and the live
FMLA vectors while visiting neighboring strips in a row block. Each output's
FMA chain continues from its previous state; coefficients are still fully
repacked every call. State is private to the worker's currently claimed batch.

Job `1579709` completed on cn20481, 19:24:27–19:28:11 +08:00. Baseline and three
carry candidates each passed eight tall signed cases with two workers (forcing
multiple strips and block crossings), then 103 generalized signed bitwise
cases. All 480 timed outputs passed reference hashes. However, the initial
batch-claim policy regressed HBM by about 21–30% across the cases.

Diagnostic job `1579727` on cn20482, about 1.2 GHz, identifies load imbalance:
for k81, baseline worker mean/max ~30.6/30.8 ms becomes ~30.8/40.1 ms with the
carry policy. Per-kind kernel cost is essentially unchanged. Filling a batch
with stolen items prematurely defeats the carefully balanced initial partition.
This rejects the initial greedy policy, not numerical state carry itself.

The next candidates claim a batch only from the worker's own queue and steal
one item only after that queue is empty; a static-only control removes stealing.
Job `1579734` tests these variants along with register scheduling candidates.

Job `1579734` succeeded on cn20481, 19:33:46–19:36:43 +08:00. Each new
variant passed 103 signed bitwise cases. The own-queue batch policy recovers
most of the previous loss: own256 improves DDR by 17.45/41.39/23.14% for
k39/k41/k55, but k81 remains 5.05% slower. HBM changes are
+0.98/−0.90/−2.41/−3.32%. own512 reduces the HBM regression to about 1–2%
for the last three cases. Neither qualifies for integration yet. The register
ping-pong and look-ahead candidates do not improve the main kernel consistently.

The resumable candidates publish each strip's ZA/FMLA state after every block,
allowing another worker to acquire and continue the remaining work. A busy bit
protects exclusive execution and acquire/release protects state transfer.
All progress metadata is reset and all coefficients are repacked on each call.
Job `1579757` tests 128/256/512-row blocks and a gather-packing combination.

Job `1579757` completed on cn20483 at 19:48:52 +08:00: all five variants
passed the eight tall signed cases and 103 generalized signed bitwise cases;
600 timed outputs passed reference hashes. resume256 improves DDR by
42.28/55.10/27.71% for k39/k41/k55, with k81 −1.16%. HBM changes are
+1.74/+0.87/−0.29/−0.88%. Adding serial gather packing gives
+2.59/+1.80/−0.15/−0.90% in HBM. A 512-row block further reduces the
k55/k81 regression, at the cost of some DDR locality in the first two cases.

Another hypothesis targets arithmetic utilization: distribute FMLA chains
across multiple pair groups when a structural cost model predicts fewer total
tile steps. For example, 81 residual rows can use 36+33+8+4 rather than
32+33+16. This requires distinct FMLA residual indices per group. The generator
enumerates group counts and retains the original plan unless the predicted
weighted cost decreases by at least 1%; it does not match published dimensions.
Job `1579768` tests minimum/maximum folds among equal-cost plans and a carry mix.

Job `1579768` succeeded on cn20486. The minimum-fold plan improves k81 by
only 0.83% DDR / 0.82% HBM; other shapes have no meaningful improvement.
The maximum-fold alternative and the own-queue carry combination are worse.
Compiler warnings about the missing `fabs` declaration in this experimental
generator need cleanup before any integration; the tested compiler recognizes
its builtin and numerical checks passed. This is not an accepted standalone gain.

## Sharing tables within a call

Every full sixteen-row R table has identical coefficients irrespective of its
group's residual offset: the offset changes the starting row cursor, not the
packed values. `share_tables` aliases these tables within the freshly built
plan, packs only the owning group, and retains per-call rebuilding. No content
is reused across calls. This reduces both duplicate packing and the number of
distinct cache lines used by different groups.

Job `1579779` compares sharing alone, sharing plus serial gather packing,
256/512-row resumable combinations, and the minimum-fold combination. Separate
state validation compiles with the plain `gcc -O3 -fopenmp ... -lm` command,
sweeps every KH from 16 through 256, changes shapes/data between long calls,
and checks retained allocation reuse.

## Vectorized coefficient packing

SVE gathers read the sixteen row-offset coefficients and write a contiguous R
vector. Predicates preserve the exact zero-padding rules and FP32 bit patterns.
The gather experiment also includes a serial-packing control and a carry mix.
Job `1579719` completed on cn20483 at 19:30:37 +08:00. Three candidates passed
123 signed bitwise cases each; the carry mix also passed the tall suite. All
480 timed outputs passed hashes.

The serial gather variant changes HBM rates by approximately −0.29/+0.38/
+0.58/+0.78%, with similarly small or mixed DDR changes. This alone does not
meet the requested stable, meaningful performance gain. The carry mix inherits
the initial batch policy's regression and is rejected.
