# 轮间输出哈希的测量对照

多次K4候选的快速初筛正向、原始基准未复现。逐行比较固定fbench和bench_conv.c发现：
fbench在每次计时后扫描整个输出计算并行哈希，并逐次打印；原始计时循环只释放输出副本。
两者的初始参考计算、分配数量、校验方式也不同，不能称为完全相同的运行环境。
这些差异只是候选解释，不能直接当作过去性能偏移的唯一原因。

本次仅在独立driver中加入SCREEN_HASH_EACH诊断入口，保持同一算子二进制不变：

- each：五次计时输出均校验哈希。
- last-only：前四次不做哈希，最后一次仍做哈希，日志明确标为UNCHECKED/PASS。

两模式都保留首次校验哈希、原有预热、分配/复制/释放和打印流程，且FBENCH_FORCE始终unset。
使用固定上游08400a76与被拒绝的indexed-all d56e8e9b；未修改正式bench_conv.c、编译命令或算子。
这不是新的生产候选，也不是直接替换正式参考的基准。
