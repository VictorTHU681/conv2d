# v56 experiment — bound the first-row copy to live input

Final status: the correction-only candidate is accepted as local v56; all
acceptance jobs completed. Earlier pending statements below preserve the
investigation timeline. The final results and decision are at the end.

## Confirmed source-level issue

`fill_args` aligns `P->in_row` down to a 64-byte boundary, adds the prefix
length to `ncp`, and calls `roll_copy_row(P->ring, src, ncp)`. When the input
object begins at a non-64-byte-aligned address and the first piece begins at
row/column zero, this copies up to 15 floats before the input object. Those
floats are not used in output arithmetic but reading them is outside the
provided input span. Standard malloc often leaves the preceding bytes mapped;
page guards after the input do not expose this leading object-boundary read.
This is inherited by accepted v56 and v55, not introduced by the new clone.

## Candidate correction

Keep the aligned ring layout and subsequent-row copier, but initialize the
first row with `roll_copy_row(P->ring + sh, P->in_row, ncp - sh)`.
The unused ring prefix is not read by the arithmetic, whose base is ring+sh.
Compute the aligned address used by subsequent assembly rows with uintptr_t
arithmetic instead of forming an out-of-object C pointer by subtraction.
The next-row copy reads from later input rows; the final-row self-copy cannot
be the first input row for these rolling groups (KH >= 16).

Controls generated by `tools/gen_v56_first_copy.py`:

- `baseline`: accepted v56, immutable `72b10c2:conv2d.c`.
- `firstsafe`: baseline plus only this first-copy correction.
- `selectsafe`: structurally selected aligned three-fold copier plus correction.

Production source and packages have not yet changed. No push.

## Diagnostic scope and performance screen

Separate `_audit` builds count every `roll_copy_row` source interval and
compare it against the current input object. This checks the helper's actual
requested span; it is not a general dynamic memory checker for all assembly.
The audit build is never used for performance measurement.

`tools/test_v56_first_copy.c` exercises all 16 float offsets within a 64-byte
line, KH 39/41/55/81/113/231, representative KW 3/17/81/400 and output width
257: 96 cases per candidate. Each call overwrites the output and checks full
bitwise agreement against the reference with signed random inputs. Bytes
outside the selected logical input span are filled with NaNs. The baseline
must exhibit at least one out-of-input helper request; both corrected
candidates must exhibit zero. This makes the baseline a positive control for
the boundary diagnostic, rather than mistaking correct values for valid reads.

## Completed screen and decision

The diagnostic observes 2,288 helper calls per variant. The baseline has
**255 out-of-input source intervals**; both fixes have **zero**. All 96
alignment cases per variant remain bitwise correct. This reproduces the
unused-prefix read, rather than inferring memory safety from output accuracy.

The corrected selective copier does not retain a k39 DDR gain; the HBM gain
is small and k55 regresses 0.21%. Do not promote the cloned kernel. Advance
**only firstsafe**, the boundary correction, to formal acceptance. It trades
a possible small performance cost for removing an invalid input read.
No cumulative gain is inferred from separate-node screening percentages.

**Decision:** accept `firstsafe` as current local v56, SHA-256
`595d7f7d88dd9bfe2ddbbff6fb50251ade05692ad876a88926999ca194102339`.
The input-boundary fix is justified independently of speed. k41 loses
0.87% DDR / 0.35% HBM against the previous v56 in this formal comparison;
this remains a performance issue to optimize, not a gain to conceal.
The earlier k81 +2.12% / +1.86% measurement used the initial v56 source and
a different run; comparing those percentages directly would confound the
repair with node/run variation. Here the repair itself leaves k81 essentially
unchanged (+0.05% / +0.01%).

The selective three-fold copier is not merged. The default source remains
free of benchmark-dimension equality dispatch and cross-call result reuse.
Formal compile command, benchmark and run scripts remain unchanged.

with the final README, with all other members required to match job 1581982's
