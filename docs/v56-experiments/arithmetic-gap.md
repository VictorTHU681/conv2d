全部通过严格解析。全部调用的线程工作量与分区总数一致，同形状工作量和表大小不变。

## 结果

四 FMOPA 的纯寄存器步约 **5.1616 ns**；同一步再加八条独立 indexed FMLA，仍约
5.1616 ns。每轮前后 mix0 中位数漂移不超过 0.008%，mix8 不超过 0.016%；
原始所有样本和偏慢样本保留，没有剔除。增加到十条及以上 FMLA 后，该探针明显变慢。
这测的是独立累加器的持续吞吐，不是单条指令延迟，也不证明任意实际混合均免费。

按源码记录的 FMOPA tile steps 计算参考：
`tile_steps / 4 × 同轮前后平均 ns/step / 38 / 1000` 微秒。
工作量包括分块预热和补齐执行；不是硬件指令计数器读数。每个 bucket 均按实际步数记录，
K4/K5 分别包含 KW+3 / KW+2，K8/K9 每双步的八个 FMOPA 折为对应 tile steps。

HBM 无插桩总耗时 / 参考依次为 **1.124、1.137、1.075、1.074**。
DDR41 主计算组每线程均时 4653.7 µs，参考 4352.2 µs；K5 为 1040.3 对 791.1 µs。
DDR81 主计算组绝对差仍较大：19245.4 对 18448.2 µs，不能只看尾组比例就排除主组。
DDR 工作线程最后结束减平均结束为 28.8、41.7、51.7、150.2 µs；是分布描述，
不是已证明可消除的同步等待。准备阶段约 17–23 µs，分发约 2–3 µs。

参考假设独立寄存器运算、理想均衡；实际内核还要加载、拷贝、搬运 ZA、处理输出及调度。
**这不是严格架构下界，也不是必然可回收的提速空间。** 主组的 4–7% 差与尾组的较大比例差，
支持优先继续拆解 K5 的平面拷贝、输出事件和状态传输，但不能据此认定其中某项是硬件瓶颈。
mix8 只是混合算术敏感性参考，不是每个分组指令构成的精确模型。

profile 的进程总计时比 plain 高 **2.77–12.64% DDR、3.07–12.04% HBM**，
其中包括线程诊断的格式化/打印。分区计时也包含参数准备和 ZA 恢复，插桩会扰动执行。
因此只用它定位区域，性能采用仍须不插桩对照和原始完整参考验收。

本轮新增的是瓶颈证据，没有新的已验收加速，不能叠加到既有 v55 提升表。
