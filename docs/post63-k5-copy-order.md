# 已采用标量展开之后的 K5 拷贝次序

本轮开始时再次 pull，远端仍为 v63 `2f00ef6`；本地默认是已验收的 `ce57939`，
源码 SHA-256 `0136da05ea4658fb5792412e95baaec0e38ff299b176e5de681f228bca88da93`。
不 push，不给内部实验分配新发布版本。

K5 已把下一行输入的完整 LD3W 拷贝穿插在部分计算外步中。当前每步先做三次 K5_STEP
（12 次 FMOPA），再连续加载并写出下一行的三个平面。本轮检查这段集中访存的次序：

- `early`：把已有的三个预取和 LD3W 提到三次 K5_STEP 之前，三个平面仍在计算后连续写入。
- `spread`：同样提前加载，随后在每次 K5_STEP 后分别写入一个平面。

两者均保持原有指令/宏的多重集合、三次 K5_STEP 的先后顺序、所有游标更新及循环控制。
没有增加访存、预取、算术或新的运行期配置。只有进入已有穿插循环后才移动这些指令，
不跨过 `ovn == 0` 的分支，也不越过最后一次迭代或行边界。

数据依赖检查：K5_STEP 只使用 z0..z4、其输入平面游标和系数 x2，不使用拷贝的
z25..z27、x12/x13/x21/x24。三个当前行平面读取与下一行写入位于已有的不同环形槽；
槽切换、stride、输入读取总长和首行初始化不变。三个计算游标与系数游标仍在全部三次
计算之后递增，三个拷贝游标仍在加载/存储之后递增。x24 的两次平面地址递推先后不变，
计算宏不改 x24。FMA 链及标量尾部展开保持已采用实现的顺序。
