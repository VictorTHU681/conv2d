# F3 展开段布局隔离（已完成，不采用）

F3 u4 在两个节点均稳定改善 KH55：DDR +0.36%/+0.49%、HBM +0.30%/+0.40%，
两种内存分别12/12配对为正。但第二节点HBM81回退0.20%，故暂缓整体采用。
新的实验保留同一展开计算，同时恢复其他热循环的原始机器码位置，检验布局是否相关。
不把相关性提前当成因果，也不通过重复同一程序追逐更好的数字。

[生成器](../tools/gen_post64_pairf3_island.py) 从138dcac原源码生成，
island SHA-256：`9323100665d25b4706a9e698b2ab941520ecab1f228d12923bdfbcd2acc1c495`。
u4 对照仍为 `f88b3f90295fd5ad5a749016343b266535857b53d2588801f65e18e6c7f2d499`。

原 F3 纯计算循环共21条指令，在原位置换成一条跳转和20条不可达NOP，占用长度不变。
展开段使用GAS的.text subsection 1，由汇编器排在本对象的常规函数代码后，
末尾显式跳回原行尾；仍在同一个扩展asm内，寄存器、内存和条件码clobber保持原样。
每行多一次进入和一次返回跳转，原u4内部的分块、余数、访存和FMA顺序不变。
没有C函数调用、栈参数传递或额外SME启停。

[机器码审计](../results/post64/pairf3-island/instruction_audit.txt) 通过：

- 原21条位置为0x423da0..0x423df0，变成入口分支加20条NOP。
- 其余2,434条roll_worker指令字节及地址完全相同，包含其他内核路径。
- 独立区域0x42b8c0..0x42ba3c，95条u4设置/计算/余数指令及相对跳转目标相同，
  最后返回原行尾0x423df4。零完整块和零余数出口也已核对。

其他函数中引用常量的指令和最终段位置仍会变化，因此不是全二进制一致。
objdump把尾部代码归于最近的前置符号conv2d；实际通过上述直接分支到达，不是调用该函数。
这段代码在编译器生成的原函数范围之外，采样符号归属及栈回溯范围不能按普通内联代码假定；
候选不改变栈指针；下方动态验证已经完成，但静态布局本身不能作为采用依据。
