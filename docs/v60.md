# v60 prepared control — fold count versus input copy

Prepared, not yet submitted or accepted. Continue local optimization, report
each round, and push only on explicit user request. Production remains v56.

Baseline is immutable 72b10c2:conv2d.c. The default k39 plan is 36+3; forcing
three folded rows gives 35+4 with the same matrix-step count. The latter fills
the K4 group's unused fourth residual and needs fewer vector FMLA instructions,
but its pairf3 uses ROW_HEAD_COMMON while pairf4 uses ROW_HEAD_COPY4.

Controls from tools/gen_v60.py:
- baseline: exact v56;
- nf3: existing three-chain compile-time control only;
- f3copy: nf3 plus COPY4 only in pairf3;
- f3copy128: f3copy plus hoisted 128-byte inner-loop alignment, using the same
  fixed macro-instruction counting technique validated for pairf4 in v55.

No arithmetic order or coefficient-caching rule changes. The copy macro's
registers are already clobbered by pairf3. Its label 43/44 does not conflict
with the function's event labels. The upcoming job runs 261 state cases for
each changed candidate, then three alternating process rounds across all four
shapes and DDR/HBM. Do not infer a speedup from a lower FMLA count alone.

Local Python compilation and shell syntax checks pass. Server compilation,
correctness and timing have not run yet. Sources are under build/v60, hashes
in results/v60/sources.sha256; job script is jobs/v60_fold_copy_job.sh.
