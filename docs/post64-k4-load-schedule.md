# K4_STEP 加载调度

基线为上游138dcac / 08400a76，不组合未采用的标量复制候选。
K4每步原来依次加载四个输入向量、一个系数向量，再执行四条FMOPA。
尝试让系数更早准备，或在FMOPA之间加载后续输入，以检验是否能减少等待。

- bfirst：先加载系数，再加载四个输入，最后执行原顺序四条FMOPA。
- interleave：依次为B、A0、A1、FMOPA0、A2、FMOPA1、A3、FMOPA2、FMOPA3。

每步仍为原来的九条指令，每个载入和FMOPA恰好一次，所有加载都先于使用它的FMOPA；
没有扩大访存区间，没有修改累加次序、整块复制、预取、分派或线程调度。
两个候选只改变真实使用的K4_STEP宏，不改未使用的K4_CP宏。

[生成器](../tools/gen_post64_k4_load_schedule.py)、[源码清单](../results/post64/k4-load-schedule/sources.sha256)。

实际二进制中，K4有11个展开的九指令块（四个穿插步骤、四个纯计算步骤、三个尾步骤）。
bfirst和interleave的全部块都严格符合预期排列，分别改变55/77个指令位置；
所有块外的指令和地址完全一致，全程序FMOPA/FMLA指令及操作数的顺序一致。
首次识别器同时匹配了其他内核的四个类似块；改为用K4循环设置与输出事件标识边界，
再逐块检查11个真实K4步骤，并严格比较所有块外代码，未放宽对其他内核不变的要求。
