## Hypothesis and controls

K9 grouping uses two kind-35 pair kernels. Their four-chain coefficient tables
are identical: each row contains coefficients from kernel rows y through y+3,
regardless of which output residuals the pair handles. For KH=KW=81, each table
contains 81*81*4 floats = 104,976 bytes (about 103 KiB). Separate copies may
increase active cache footprint and per-call packing work.

`tools/gen_v57.py` generates three controls from immutable v56:

- `sharekf`: alias tables only when kind and padded step count match, and pack
  the first owner on every call. Aliases belong to the call's plan; persistent
  buffer slots retain allocation ownership. Earlier groups are checked before
  allocating, so a first-time alias does not allocate an unused duplicate.
- `veckf`: load coefficient rows using predicated SVE vectors and interleave
  stores with ST4. Tail lanes read only real coefficients; unused lanes are
  zero. Kind 34 still has a zero fourth lane, so it is not shared with kind 35.
- `sharevec`: combine both controls.

No coefficient content is cached between calls, and no output arithmetic or
FMA ordering is changed. The state sweep covers every KH from 16 through 256
and repeated multi-block shape/input/coefficient changes. Allocation-reuse
checks verify bitwise outputs and no additional aligned allocations after
warmup. All four official shapes are screened because compilation changes can
also change code placement.

Baseline k81 worker time is 22,301 us DDR / 22,203 us HBM. Sharing saves
about 5–7 us in host packing, roughly 0.02–0.03% of total runtime. Even
eliminating this whole packing phase would save less than 0.5% in this
instrumented workload. Observed worker-time differences do not establish a
stable cache benefit and are not promoted as a throughput result.

The 2 MiB tracked-allocation reduction is explained by `alloc_aligned()`:
it rounds each requested buffer to a multiple of 2 MiB. Avoiding the duplicate
~103 KiB table therefore avoids a 2 MiB aligned request in the reuse test.
This remains an allocation metric; RSS was not measured.

**Decision:** retain validated v56 unchanged. Neither sharing, vectorized
packing, nor their combination is accepted as a performance improvement.
The memory-saving variant remains reproducible for future resource-pressure
investigation. Further throughput work should target worker computation/load
cost, which dominates the measured total, rather than this small packing phase.
