# PAIRF3 纯计算循环展开（v65 采用）

最终状态：三方作业1593234已完成，本次采用普通u4并汇总为v65。
三轮KH55 DDR/HBM均为正，其他形状有波动和回退；完整依据见 [v65](v65.md)。
下文按实验进程保留此前暂缓采用的判断，最终决定以本段和文末为准。

紧凑系数布局在原始对照中使 KH55 两种内存均回退约 0.6%，已拒绝。
本项从上游 138dcac 原源码重新生成，保留原四系数布局，每四步合并三条系数游标更新，
减少循环控制开销。没有组合紧凑表、K4 地址/事件或旧 F4 候选。

源文件 SHA-256：

- 基线：`08400a7659134bf7bee3b14df24fc919537c9fef634d1b580bf66fba0b112357`
- u4：`f88b3f90295fd5ad5a749016343b266535857b53d2588801f65e18e6c7f2d499`
- 未修改原始 bench_conv：`2548861ae7e29826e454b4c0b098d682f7f04996222e664cd1ea9bc92dd2e927`

[生成器及模型](../tools/gen_post64_pairf3_unroll.py) 只替换 k16pairf3 内的 OVL_LOOP 实例，
共享宏和其他函数字节相同。原穿插计算/拷贝、补拷及谓词尾拷全部保留；只展开最后纯计算段。
设置 x12=剩余步数/4、x15=剩余步数%4，零完整块直接到余数检查，零余数直接到原行尾。
每步 input 游标仍加四字节；R 的两条游标用 #q,mul vl，kf 用 #16q 字节偏移，
完整四步后再把两条 R 游标加256、kf游标加64。0..3个余数步使用原 PAIRF3_STEP。
x12 在拷贝结束后可复用，步骤内不使用它，且原 clobber 已包括它。

地址模型枚举 KW1..400 的全部 80,600 个穿插步数划分，核对每步四条访问游标及行末位置，
包括防御性零剩余情况。实际 fill_args 将 ovn 限制为最多 it-1，正常路径仍至少留一步。
模型不代替动态边界测试。

[链接机器码审计](../results/post64/pairf3-unroll/instruction_audit.txt) 已通过：

- 穿插步骤和余数步骤均与原 19 条指令一致。
- 四步完整块各保留五次加载、四条 FMOPA、六条 FMLA，偏移和乘加顺序一致。
- 完整块与余数循环回跳、零块/零余数出口均指向预定位置。
- 删除新增完整块的四份乘加后，worker 剩余乘加操作数/顺序与原程序相同。

四步完整循环由 84 条变为 69 条静态指令，不含新增设置与余数处理开销。
新循环入口0x423db0，原纯计算入口0x423da0；链接地址变化，不能宣称其他机器码全部相同。
这也不是对执行端口或全部动态访存的证明。

KH55 两种内存又各6/6为正，两节点合计每种内存12/12为正；目标收益可重复。
但第二节点HBM81只有2/6为正，配对中位数-0.22%，范围-0.71%..+0.23%。
不能把这项回退隐去，也不能将未执行F3的其他形状提升直接归因于展开。
因此暂缓整体采用，保留u4为目标收益已验证的候选，默认源码和包仍不更换。
不再重复相同二进制追逐更好数字；下一步测试将展开段放到独立汇编代码区，
保留原内联代码占用长度，检查能否保留F3收益并避免改变其他热循环位置。
这只是可验证的布局假设，目前没有因果结论。

## 最终决定

[独立展开段布局](post64-pairf3-island.md) 的作业1593234已成功完成。
144次完整参考检查误差零，其中普通u4为48次；三轮普通u4累计144次。
本轮KH55普通u4 DDR +0.10%、HBM +0.08%，配对5/6、6/6为正；
三轮累计17/18、18/18为正。独立布局相对u4没有稳定的额外目标收益，不采用。
其他用例方向仍变化，包括本轮HBM41 -0.24%和HBM81 +0.24%；此前HBM81 -0.20%仍保留。
本次接受目标用例可重复的小幅收益，采用普通u4，承认其他形状的性能限制，汇总为v65。
正式包与上述已验收隔离包仅README不同，程序成员相同；旧归档哈希仍指历史隔离包。
最终包见 [v65清单](../results/v65/archives.sha256)，发布依据见 [v65](v65.md)。
